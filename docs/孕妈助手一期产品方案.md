# 孕妈助手一期产品方案

## 1. 产品定位

**暂定名称：孕期好好过**

面向孕妈及其家人的微信小程序。它以孕周为主线，把每天应该关注的饮食、作息和注意事项整理为容易执行的小任务；家人可同步查看进度并提供日常支持。

一期的目标不是提供诊断或替代产检，而是帮助用户建立稳定的孕期生活节奏、理解当前孕周的常见变化，并让家人知道如何配合。

### 一期成功标准

- 用户能在 1 分钟内完成预产期或末次月经日期设置，并看到当前孕周和怀孕天数。
- 用户每天打开首页，即可知道今天的饮食、生活建议和需留意事项。
- 家人通过邀请进入同一家庭后，可看到同一份孕期进度和待办，不必反复询问。
- 用户可随时修正日期，孕周、每日内容与提醒自动随之更新。

## 2. 一期范围

### 必须上线

| 能力 | 用户价值 | 一期说明 |
| --- | --- | --- |
| 孕期档案与日期计算 | 明确今天处于第几天、第几周 | 支持末次月经日期、预产期两种录入方式；展示孕天、孕周、距预产期天数；允许重新编辑。 |
| 今日孕期指南 | 每次打开都有明确行动 | 提供当日饮食建议、生活作息建议、注意事项和轻量待办。 |
| 每周孕期指南 | 看懂阶段变化与本周重点 | 按 4 周至 40 周展示妈妈变化、本周营养重点、生活建议、注意事项。 |
| 家庭共享 | 让家人参与但不增加孕妈负担 | 孕妈创建家庭并生成微信邀请；家人加入后共享孕期进度、每日重点与待办完成状态。 |
| 我的与设置 | 管理个人和家庭资料 | 编辑孕期日期、查看家庭成员、退出家庭、通知设置与免责声明。 |

### 一期暂不做

- 在线问诊、疾病诊断、处方、紧急医疗判断。
- 社区发帖、陌生人聊天、商品商城、课程售卖。
- 复杂的体重/血糖/胎动数据记录与图表。
- 多胎、辅助生殖、产后阶段的独立内容体系。

这些能力会显著增加医学内容审核、隐私与交互复杂度，不应影响第一期核心体验。

## 3. 用户与权限

| 角色 | 典型用户 | 主要权限 |
| --- | --- | --- |
| 孕妈（家庭创建者） | 怀孕中的用户 | 创建/编辑孕期档案；邀请或移除家人；查看和完成全部内容；管理通知。 |
| 家人 | 伴侣、父母等 | 加入家庭；查看孕周、今日重点、本周建议和共同待办；完成分配给自己的待办。不能改动孕期关键日期。 |

共享遵循“孕妈主导”原则：孕妈可以随时撤销邀请或移除成员；家人只看与孕期支持直接有关的信息。每个家庭默认最多 5 位家人，避免一期的群组管理变复杂。

## 4. 核心信息架构

```text
底部导航
├── 今日
│   ├── 孕期进度卡
│   ├── 今日饮食
│   ├── 今日生活规律
│   ├── 今日注意事项
│   └── 今日待办
├── 孕期
│   ├── 本周概览
│   ├── 周数选择（4-40 周）
│   ├── 每周吃什么
│   ├── 每周生活建议
│   └── 本周注意事项
├── 家庭
│   ├── 家庭共享进度
│   ├── 家人支持清单
│   ├── 成员列表
│   └── 邀请/管理成员
└── 我的
    ├── 孕期档案（日期与孕周）
    ├── 提醒设置
    ├── 内容与免责声明
    └── 隐私与账号
```

## 5. 底部导航规划

一期建议使用 **4 个一级 Tab：今日、孕期、家庭、我的**。

| Tab | 图标方向 | 核心问题 | 页面内容 | 原模板映射 |
| --- | --- | --- | --- | --- |
| 今日 | 日历/太阳 | “我今天该做什么？” | 孕周进度、今日三餐、生活建议、注意事项、待办 | 替换现有“首页” |
| 孕期 | 日历/书本 | “这个阶段应该注意什么？” | 本周概览、周数切换、饮食与生活专题 | 新增，替代现有“消息” |
| 家庭 | 用户组/爱心 | “家人怎样帮到我？” | 共享进度、家人待办、成员和邀请 | 新增 |
| 我的 | 用户 | “如何管理我的资料？” | 日期编辑、提醒、家庭管理、隐私设置 | 改造现有“我的” |

不建议把“消息”放在一期底栏。家庭协作初期的互动以共享状态和待办为主；在没有明确消息场景前，保留消息入口只会制造空页面。系统提醒可通过微信订阅消息和“我的 - 提醒设置”完成。

### 底栏交互规则

- 首次进入没有孕期档案时，默认落在“今日”，先展示日期设置引导；完成后再进入完整内容。
- “今日”始终是默认首页；孕期状态发生变化时，所有 Tab 使用同一份日期计算结果。
- 家人身份进入后，“今日”和“孕期”只读，“家庭”中展示可完成的支持待办；“我的”不展示孕期日期编辑。
- Tab 文案保持两字，图标采用统一线性风格，选中状态只使用品牌主色，不依赖颜色表达关键信息。

## 6. 关键页面说明

### 6.1 首次设置：建立孕期档案

1. 选择身份：`我是孕妈` 或 `我是家人`。
2. 孕妈选择计算方式：`末次月经日期` 或 `预产期`。
3. 录入日期后，展示计算结果：今天是第 X 天、第 X 周 + X 天、距预产期 X 天。
4. 用户确认后进入“今日”；在“我的 - 孕期档案”中可随时修改。
5. 家人进入时通过孕妈分享的邀请链接/二维码加入家庭，无需单独录入日期。

计算方式应始终说明为“基于用户填写的日期估算”，而不是医疗结论。日期修改后须二次确认，并立刻刷新所有日期相关内容。

### 6.2 今日页（产品核心页）

推荐从上到下按“先知道阶段，再完成今天”排列：

1. **孕期进度卡**：`孕 X 周 + X 天`、`已怀孕 X 天`、`距预产期 X 天`；点击可进入档案编辑。
2. **今日吃什么**：早餐、午餐、晚餐、加餐四个时段；每项给出食物组合、营养目的、简单替换建议。
3. **今日生活规律**：例如喝水、适量活动、休息、睡眠等 2 至 3 项；用可勾选任务呈现。
4. **今日注意事项**：最多 3 条，按“建议留意”和“需要尽快咨询医生”分级。
5. **家人可以做什么**：有家庭时展示一条可分配支持事项，例如准备加餐、陪同步行、协助预约。

默认只显示一屏半的核心信息；卡片点击后才展开详细原理、替代方案和禁忌说明，避免每日内容过载。

### 6.3 孕期页

顶部固定显示当前周数，支持查看相邻孕周，但明确标记“当前”。每周内容遵循同一结构：

- 本周妈妈可能的身体变化（不将个体差异表述为必然发生）。
- 本周营养重点和一周食物建议。
- 本周生活规律与产检准备建议。
- 本周需留意症状及就医提示。
- 家人支持重点。

### 6.4 家庭页

孕妈创建家庭后，可通过微信分享卡片或二维码邀请家人。家人加入后，页面展示：

- 当前孕周及今天/本周重点。
- 共同待办和完成状态。
- “今天可以帮她做什么”建议。
- 成员列表、邀请入口与成员管理。

涉及隐私的健康记录不在一期共享；家庭成员默认不能修改孕期档案。

### 6.5 我的页

- 孕期档案：姓名/称呼、末次月经日期或预产期、计算结果、编辑入口。
- 家庭管理：创建家庭、成员列表、退出或解散家庭。
- 提醒设置：每日指南提醒、每周更新提醒、产检提醒（仅保留开关和时间配置）。
- 内容说明：医学内容来源/审核说明、隐私政策、免责声明、意见反馈。

## 7. 内容框架与安全边界

### 饮食内容模板

每日和每周内容需要由营养专业人员审核，并使用标准化模板生成：

| 内容字段 | 示例要求 |
| --- | --- |
| 适用孕周 | 明确适用区间，如“孕 13-16 周”。 |
| 一日饮食建议 | 按早/午/晚/加餐给出食物类别和可替换组合，避免强制单一菜谱。 |
| 营养重点 | 说明为什么关注蛋白质、叶酸、铁、钙等，不宣称治疗效果。 |
| 份量表达 | 优先使用可理解的家庭份量，同时保留“因人而异”的提示。 |
| 注意事项 | 说明需充分加热、避免酒精及高风险食物等通用建议。 |
| 特殊情况 | 贫血、糖尿病、甲状腺疾病、过敏等情况提示遵医嘱，不推送通用方案。 |

### 医疗风险提示

- 不使用“保证”“一定”“治疗”等绝对或医疗化承诺。
- 对异常症状不做在线判断；使用明确的“请及时联系产科医生/前往医疗机构”提示。
- 首次使用、编辑日期、查看注意事项详情时，提供简明免责声明。
- 文案中区分“日常建议”“需咨询医生”“紧急就医”三个等级，并由专业审核确认触发条件。

## 8. 数据与规则（一期）

### 孕期档案最小字段

| 字段 | 说明 |
| --- | --- |
| 用户身份 | 孕妈或家人。 |
| 计算依据 | 末次月经日期 / 预产期。 |
| 日期 | 用户填写的对应日期，保留原始值以便再次编辑。 |
| 预产期 | 根据末次月经日期计算，或由用户直接填写。 |
| 孕周 | 由系统每天计算；以 `周 + 天` 形式展示。 |
| 孕天数 | 由系统每天计算。 |
| 家庭 ID 与成员角色 | 用于共享范围和权限判断。 |

### 日期计算规则

- 当用户填写末次月经日期：孕天数以该日期为第 1 天计算；预产期按医学常用 280 天估算。
- 当用户填写预产期：末次月经日期按预产期向前推 280 天估算。
- 系统在每天首次打开和日期编辑后重新计算孕周、孕天数及内容索引。
- 超出预设范围（如明显早于合理孕周或超过 42 周）的数据不自动给出普通饮食计划，展示“请核对日期或咨询医生”。
- 用户可以修改日期；修改需显示旧值和新值的差异，确认后同步刷新家庭可见的进度。

以上规则用于产品展示，最终计算口径应由医学顾问确认，并在产品内标注为估算结果。

## 9. 一期主流程

```text
孕妈首次进入
  -> 选择“我是孕妈”
  -> 填写末次月经日期或预产期
  -> 确认孕周估算结果
  -> 进入「今日」查看饮食 / 规律 / 注意事项
  -> 可在「家庭」邀请家人

家人首次进入
  -> 打开孕妈邀请
  -> 微信授权并确认加入
  -> 进入「家庭」查看进度与支持待办
  -> 在「今日」查看只读的当日重点

孕妈修改日期
  -> 我的 - 孕期档案 - 编辑
  -> 修改末次月经日期或预产期
  -> 查看新的孕周与预产期
  -> 确认
  -> 今日 / 孕期 / 家庭页统一刷新
```

## 10. 模板改造方向（仅供后续开发使用）

当前模板中已有“首页、消息、我的”底栏和用户中心能力。一期开发时建议：

- 将现有首页的信息流改造成“今日”仪表盘，不复用推荐流、关注流和发布入口。
- 将“消息”替换为“孕期”，并新增“家庭”一级页面；移除聊天和发布等与一期无关的入口。
- 基于现有“我的”和资料编辑页改造孕期档案、家庭管理和提醒设置。
- 保留已有登录基础能力，但需增加家庭邀请关系、角色权限和共享范围控制。

## 11. 图片与视觉待确认项

用户将提供图片后，再据其拆解和确认以下内容：

- 品牌气质：温暖陪伴、医疗可信或生活方式感的比例。
- 首页进度卡、饮食内容卡和底栏的视觉语言。
- 插画/摄影素材方向，以及是否需要孕周相关视觉变化。
- 主色、辅助色、字体层级和图标风格。

在图片确认前，界面应优先采用清晰、低干扰、易阅读的健康信息设计；避免将医学风险提示做成弱对比度的装饰性文本。

## 12. 下一步需要确认

1. 产品名称和面向的地域/内容规范。
2. 日期输入是否支持医生给出的校正孕周或 B 超预产期（建议一期先不支持，仅预留）。
3. 饮食建议是否需要考虑地域口味、素食、孕吐、妊娠糖尿病等特殊场景。
4. 家人待办是系统推荐即可，还是需要支持孕妈手动创建。
5. 用户提供的图片作为视觉参考后，确认第一版页面的样式方向。
